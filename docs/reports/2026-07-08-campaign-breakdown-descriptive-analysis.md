# Per-Campaign Descriptive Breakdown (L0 / L1 / L2)

How much data does each of the 15 campaigns actually contribute, at each
tier, and how complete is each core variable *within* that campaign
specifically (as opposed to `docs/reports/2026-07-07-data-tier-descriptive-analysis.md`'s
whole-tier pooled numbers)? This report answers that, plus the
L0→L1→L2 funnel retention per campaign, each campaign's flight-date
coverage, and two findings that only show up once you break the data
down by campaign rather than looking at it pooled.

Full CSVs: `logs/analyze_campaign_breakdown/latest/`. Figures:
`figs/analyze_campaign_breakdown/latest/`. Reproduce with
`python scripts/analyze_campaign_breakdown.py`.

## 2. L0→L1→L2 funnel retention by campaign

L1 is built by joining CPI particle images to their exact L0 second, so
L1's row count is **not bounded above by L0's** — a campaign whose camera
captured many images per second can have `l1_n_rows > l0_n_rows` (ratio
>100%). L2 filters L1 down to rows where all 7 core variables are
present.

(figure `02_funnel_retention_by_campaign.png` — CRYSTAL-FACE-UND's 800%
bar dwarfs the others on a linear axis; read the numbers above alongside
the plot rather than relying on bar height for the smaller campaigns.)

**Finding: OLYMPEX, POSIDON, and ESCAPE have zero rows at L1 and L2.**
This is not a join bug — `data/raw/cpi_embeddings_timestamps.csv` (the
canonical CPI particle-image timestamp archive `parsers/cpi_timestamps.py`
loads) contains only 12 distinct campaigns, and these three are not
among them. Their `data/raw/<campaign>/` directories also contain no CPI
raw-image subfolder (confirmed for all three), unlike the 12 campaigns
that do have L1/L2 rows. These three campaigns' env data (L0) is fully
usable for thermodynamic-only analysis, but they contribute **nothing**
to any CPI-image/morphology analysis (including
`scripts/analyze_embedding_multivariate.py` and
`scripts/visualize_embedding_colorspace.py`, both L2-based) — this should
be added to CLAUDE.md's campaign list caveats if not already implied
there. `docs/decisions/2026-07-07-cpi-env-unmatched-images-investigation.md`'s
"6.34% of CPI images unmatched" figure is about images that exist but
don't join to an env second — a different phenomenon from these three
campaigns, which have no CPI images in the pipeline's inputs at all.

## 3. Core-variable completeness by campaign (within-campaign, not pooled)

Figures `03_completeness_heatmap_l0.png` / `04_..._l1.png` /
`05_..._l2.png` (green=100% valid, red=0%). L2 is deliberately all green
(100%) by construction — the filter that defines L2 — so it's included
mainly as a sanity check.

L0 highlights (full numbers: `campaign_completeness_l0.csv`):

| Campaign | Tair_C | P_hPa | Si | qv | Lat/Lon | Alt_m |
|---|---:|---:|---:|---:|---:|---:|
| MPACE | 58.8% | 100% | **0.0%** | **0.0%** | 89.4% | 89.4% |
| ATTREX | 44.0% | 44.0% | 37.6% | **91.4%** | 43.9% | 43.9% |
| MIDCIX | 41.8% | 41.8% | 41.8% | 41.8% | 100% | 98.2% |
| CRYSTAL-FACE-NASA | 50.2% | 100% | 50.2% | 50.2% | 99.9% | 99.9% |
| ARM | 99.0% | 100% | 36.4% | 36.4% | 91.7% | 100% |

- **MPACE: Si/qv are 0% valid, every single record** — not a bug.
  `config.yaml`'s MPACE entry documents it directly: "No water-vapor
  instrument was flown, so Si/qv are NaN for every record." This single
  fact fully explains MPACE's `l1_to_l2_pct = 0.0%` in §2 — every MPACE
  L1 row fails L2's core-variable-complete filter on Si/qv alone, so
  MPACE (like OLYMPEX/POSIDON/ESCAPE, for a different reason) contributes
  **zero rows to L2** and to any L2-based CPI/env analysis.
- **ATTREX's qv (91.4%) is dramatically more complete than its own
  Tair_C/P_hPa/Lat/Lon/Alt_m (all ~44%)** within the same campaign — a
  different subset of instrument-seconds populates qv than populates the
  other core variables for this campaign, worth knowing before assuming
  ATTREX rows are "core-variable complete" just because qv looks fine.
- **MIDCIX is uniformly ~42% for Tair_C/P_hPa/Si/qv but 98-100% for
  Lat/Lon/Alt_m** — consistent with CLAUDE.md's documented note that
  MIDCIX's navigation (FP) files cover 2 more flight dates than the
  water-vapor (JW) files `load_midcix()` keys rows off of.
- Every other campaign (AIRS-II, ICE-L, ISDAC, MC3E, IPHEX, ESCAPE, and
  both CRYSTAL-FACE variants for non-Si/qv vars) sits at 90-100% for
  Tair_C/P_hPa/Lat/Lon/Alt_m — the L0 tier's well-known ARM-driven Si/qv
  gap (CLAUDE.md: "ARM qv NaN: 63.6% NaN, real data sparsity in dry upper
  troposphere") is visibly an ARM-and-a-handful-of-others pattern, not a
  dataset-wide one, once broken out by campaign.

## 4. Flight-date coverage

Figure `06_date_range_by_campaign.png` — a timeline of each campaign's
first-to-last L0 Timestamp. ATTREX is a clear outlier: a 2.4-year span
(2011-10-28 to 2014-03-15, 36 distinct flight dates) vs. every other
campaign's single-season-or-shorter deployment (all ≤36 days of actual
first-to-last calendar spread except ATTREX). This matches its L0 row
dominance in §1 — ATTREX isn't just a long-duration campaign, it's an
order of magnitude longer than anything else in the dataset, which is
exactly why it can be 26.3% of L0 rows while flying instruments no
different from the other campaigns. Chronologically the 15 campaigns
span 2000 (ARM) to 2022 (ESCAPE) — a 22-year instrument/campaign range,
worth keeping in mind for any analysis that assumes measurement
consistency across the full dataset (CPI camera models, calibration
practices, etc. plausibly differ across that span, independent of the
already-documented per-instrument H2O ranking differences in
`config.yaml`).
