# In-Situ Turbulence Measurements: What Exists in the Raw Data, By Campaign

## Why this survey

The combined dataset (`data/out/combined_env_data*.parquet`) currently carries
thermodynamic and microphysical variables only (Tair_C, P_hPa, Si, qv, Lat,
Lon, Alt_m, CPI images). It carries nothing about atmospheric turbulence —
no vertical wind, no eddy dissipation rate, no aircraft attitude. This
matters because turbulence is a first-order control on ice-crystal habit and
mixing near cloud boundaries, and several of these campaigns flew dedicated
gust-probe/turbulence instrumentation that has simply never been touched by
any parser in this repo.

This report answers one question per campaign: **does the raw archive
contain in-situ turbulence-relevant measurements, and if so, is any part of
the current parser already touching them?** It does not recommend a specific
implementation — see "Recommendations" at the end for the tradeoffs to weigh
before doing so.

**Method:** four research passes, split by raw-file format family (NetCDF;
NASA-ICARTT `.ict`; campaign-specific fixed-column text; ARM's proprietary
binary), each inspecting representative raw files' headers/variable
metadata directly and cross-referencing every `parsers/<campaign>.py` for
whether the variable is read into memory, and if so, whether it survives
into that parser's `extract_*_standard()` output. All 15 campaigns in
`CLAUDE.md`'s campaign list are covered below.

## Headline finding

**Every one of the 15 campaigns has at least a true-airspeed channel, and 13
of 15 have a directly-measured 3-D wind vector (including vertical wind)
sitting in the raw archive.** In 11 of those 13 cases, the relevant columns
are *already parsed into an in-memory DataFrame* by the existing loader
function — they just never make it into that same function's
`extract_*_standard()` output. Adding them would not require touching the
raw files or file-discovery logic for those 11; it would mean adding a
handful of dict keys to a function that already has the data in scope. The
remaining cases (AIRS-II, ICE-L, ISDAC's high-rate source, ESCAPE's
NRC-Convair source) would need a new read path added, since those variables
are never dereferenced by the current xarray/CSV loaders at all.

The one campaign with essentially nothing beyond airspeed is **MIDCIX**
(raw archive here never received the MMS meteorology/turbulence product
that its sibling campaign CRYSTAL-FACE-NASA did, despite flying the same
WB-57/MMS instrument system).

## Instrument-lineage families (why variable names repeat across campaigns)

The turbulence-relevant variables cluster into three families by ground-
processing pipeline, which is useful context because it means the unit and
naming inconsistencies below are systematic, not random:

- **NASA Ames MMS** (T. Paul Bui/GSFC gust-probe system, various aircraft):
  `W`/`U`/`V` (m/s, linear), `TEDR` (**log10** kW/kg), `REYN` (log10
  Reynolds number/length), `ROLL`/`PITCH`/`HDG`. Used in **ATTREX,
  POSIDON, MACPEX**, and (as `MM`/`MG` files) **CRYSTAL-FACE-NASA** and
  (as `FP`) **MidCiX**.
- **UND Citation ground-processing pipeline** (Poellot/Delene, University
  of North Dakota): `Wind_Z`/`Wind_M`/`Wind_D`, `TURB` (**linear**
  cm^(2/3)·s⁻¹ EDR-type units), `POS_Pitch`/`POS_Roll`/`POS_Head`,
  `POSZ_Acc`, `Alpha`/`Beta` (angle of attack / sideslip — the only
  family that reports these explicitly), `VERT_VEL`. Used in
  **CRYSTAL-FACE-UND** (`MET.CIT`/`NAV.CIT`), **MC3E**, **MPACE**,
  **OLYMPEX**, **IPHEX**. ARM's proprietary binary format
  (`Vertical_Wind_m_s`/`Turbulence_eps`) is the same PI/aircraft lineage
  as MPACE (Poellot Citation) but predates the ASCII product and uses a
  different (linear, undocumented-scale) `Turbulence_eps` convention.
- **NCAR/NRC RAF-Nimbus convention** (research-aircraft NetCDF standard):
  `WI`/`WIC` (vertical wind, CF `standard_name=upward_air_velocity`),
  `PITCH`/`ROLL`/`THDG`, `ACINS` (vertical acceleration),
  `ATTACK`/`SSLIP`, `TASX`. Used in **AIRS-II**, **ICE-L**. A closely
  related but distinct NRC-Convair scheme (`VWND_P`, `TDREDDY` eddy
  coefficient, `PRATE`/`RRATE`/`YRATE`) appears in **ISDAC**'s
  `wolde-convair` source and **ESCAPE**'s `atmospheric-and-aircraft-state`
  source.

Any future unification work will need to reconcile at minimum: `TEDR`
(log10 kW/kg) vs. `TURB` (linear cm^(2/3)·s⁻¹) vs. ARM's `Turbulence_eps`
vs. ISDAC's `TDREDDY` (a proprietary TAMDAR coefficient, not a standard EDR)
— these are not the same physical scale and should not be concatenated
without conversion.

## Per-campaign detail

### ARM
- **Raw format:** proprietary binary, `citation.<MMDDHHMMSS>.t4archive.gz`, decoded by `parsers/arm.py`'s 39-field `ARM_COLUMNS` unpacker (confirmed against `data/raw/ARM/poellot-citation-t4-readme.txt`).
- **Native rate: 4 Hz** (0.25 s steps) — confirmed empirically by decoding a file. This is the highest native rate of any campaign except ISDAC's unused 5 Hz source, and conflicts with this repo's exact-second merge convention (`round_timestamp_to_second`) since `parsers/arm.py` is the only parser that does **not** call it — its `Timestamp` retains sub-second precision.
- **Variables found:** `Vertical_Wind_m_s` (direct vertical wind), `Turbulence_eps` (turbulence/EDR-type field, readme labels it "Turbulence"), `True_Air_Speed_m_s`, `Wind_Speed_m_s`, `Wind_Direction_deg`, `INS_Heading_deg`, `Pitch_deg`, `Roll_deg`.
- **Parser status:** all 8 already **decoded into the DataFrame** returned by `load_arm_file()` (`parsers/arm.py:110-123`). `extract_arm_standard()` (`arm.py:312-347`) drops all of them.
- **Caveat:** any addition here forces a decision — floor to 1 Hz like everything else (discards 3 of 4 samples) or carry sub-second data outside the current L0/L1/L2 scheme.

### AIRS-II
- **Raw format:** NetCDF, RAF-Nimbus convention, 1 Hz "LRT" (low-rate) product only — no high-rate file exists in this archive, even though several variables' metadata (`SampledRate=250`, etc.) documents the aircraft's original pre-decimation sampling rate.
- **Variables found:** `WI`/`WIC` (vertical wind, GPS-corrected variant), `WS`/`WSC`/`WD`/`WDC` (horizontal wind), `PITCH`/`ROLL`/`THDG`, `ACINS` (vertical acceleration), `ATTACK`/`AKRD` (angle of attack), `SSLIP` (sideslip), `TASX`/`TASF`/`TASHC`/`TASR`, `WP3` (damped aircraft vertical velocity), raw dynamic pressures `QCF`/`ADIFR`/`BDIFR`.
- **Parser status:** `parsers/airs_ii.py` only reads `RHUM`, `ATX`, pressure, and position — **none of the above are ever dereferenced** (xarray opens lazily; unread variables are simply never touched). Would need new `ds["WIC"]` etc. reads added.

### ATTREX
- **Raw format:** NASA-ICARTT `.ict`, MMS instrument file separate from the water-vapor files (DLH/NOAA/UCATS, which have zero turbulence content). 1 Hz.
- **Variables found:** `TAS`, `U`, `V`, `W` (vertical wind, header states "1-sigma uncertainty of the 3-D wind vector is ±1.0 m/s" — a genuine 3-D wind product), `TEDR` (log10 EDR), `REYN`, `ROLL`, `PITCH`, `HDG`. No angle-of-attack/sideslip in this family.
- **Parser status:** `_parse_ict_file()` reads every MMS column generically (prefixed `MMS_*`), so all 9 exist in the merged in-memory DataFrame; `load_attrex()`/`extract_attrex_standard()` only ever reference `MMS_T`/`MMS_P`/`MMS_G_LAT`/`MMS_G_LONG`/`MMS_G_ALT`. Zero other references confirmed by grep.

### CRYSTAL-FACE-NASA
- **Raw format:** WB-57 `.WB57` files, 19 instrument subdirectories, all 1 Hz except MP (15 s) and ALIAS (2 s)/HW (10 s, both non-turbulence).
- **Variables found, by subdirectory:**
  - `MM` (read+discarded): `U`, `V`, `W` (vertical wind) — parsed by `load_mm_met_file` (arm... i.e. `crystal_face_nasa.py:309-372`) but the function returns only `Timestamp/P_hPa/T_K/source_file` (line 372).
  - `NP` (read+discarded): `Pitch`, `Roll`, `TAS`, `gSpd`, `trkA`, `T_Head` — parsed by `load_np_file` (lines 136-199) but only `Timestamp/Lat/Lon/Alt_m` returned (line 199).
  - `NM` (read+discarded): `WindSpd`, `WindDir`, `Mach` — parsed by `load_nm_met_file` (lines 438-483), only `Timestamp/P_hPa/T_K/source_file` kept.
  - `MG` (**never touched at all**): log10 EDR (`TEDR`-equivalent, labeled "Log10 of Turbulent Eddy Dissipation Rate") and log10 Reynolds number. Zero code references anywhere in `crystal_face_nasa.py`.
  - `FP`, `FT`, `PT`, `MP` (**never touched at all**): additional TAS, horizontal wind speed/direction, dynamic-pressure components, MTP-derived pitch/roll — none referenced in any parser code.
- **Caveat:** file headers (in FP/MG) document a 20 Hz raw MMS stream (full turbulence suite including angle of attack, yaw, second-derivative accelerations) as "available upon request" from the original PI — **not present in this repo's archive at all**, only the 1 Hz downsampled products above.

### CRYSTAL-FACE-UND
- **Raw format:** UND Citation `.CIT` files. `ND_MET` (meteorology) and `ND_NAV` (navigation) subdirectories are separate from the humidity file (`ND_MIS`) the parser is keyed off. 1 Hz throughout.
- **Variables found:** `Wind_Z_Nose` (vertical wind), `Wind_M_Nose`/`Wind_D_Nose` (horizontal wind), `TURB` (EDR, cm^(2/3)·s⁻¹, all in `ND_MET`); `POS_Pitch`, `POS_Roll`, `POS_Trk`, `POS_Head`, `TAS_n`, `POS_Spd` (all in `ND_NAV`).
- **Parser status:** `_read_met_cit_file()` (`crystal_face_und.py:61-88`) parses **every** column in both MET.CIT and NAV.CIT headers (it's reused for both files, line 125). But `met_cols_to_merge` (lines 169-173) and `nav_cols_to_merge` (lines 126-128) only keep Timestamp/Tair/pressure and Timestamp/lat/lon/alt respectively — every turbulence field is parsed then dropped before merge.

### ESCAPE
- **Raw format:** two independent sources from two different aircraft flying alongside each other.
  - `atmospheric-and-aircraft-state/*.nc` (NRC Convair-580) — **entirely unused by the pipeline**, zero references anywhere in the repo. 1 Hz. Contains `wind_v` (Rosemount 858 probe vertical wind), `wspd`/`wdir`, `roll`/`pitch`/`hdg` (KVH INS), `TAS`.
  - `spec-learjet-state/*/ESCAPE-Page0_Learjet_*.ict` (SPEC Learjet 35) — **this is the file the parser actually reads** (`config.yaml` path/pattern). Contains `VaV` (vertical wind, "Met_WWindSpeed_InSitu_None"), `Hdg` (heading only — no pitch/roll/attitude-rate), `TAS`.
- **Parser status:** `load_escape_file()` reads `VaV`/`Hdg`/`TAS` into the raw per-file DataFrame via generic CSV ingestion, but `_choose_column()` only looks for Temp/Dew/Pressure/Palt/Lat/Long/Time (lines 261-271) and `extract_escape_standard()` (lines 418-451) never surfaces them.
- **Caveat:** the unused NRC-Convair source is a *different aircraft's flight track* than the Learjet data the pipeline currently uses — richer (has attitude), but not simply mergeable with the currently-ingested Learjet stream without reconciling two separate trajectories from a coordinated flight leg.

### ICE-L
- **Raw format:** NetCDF, RAF-Nimbus convention, `nav-state-microphysics/*.nc`, 1 Hz "LRT" product (same family as AIRS-II, richer variable set).
- **Variables found:** `WI`/`WIC` (vertical wind), `WS`/`WSC`/`WD`/`WDC`, `PITCH`/`ROLL`/`THDG`, `ACINS`, `ATTACK`/`AKRD`/`SSLIP`, `TASX` family, plus (beyond AIRS-II) `BPITCHR`/`BROLLR`/`BYAWR` (body angular **rates**), `BLATA`/`BLONGA`/`BNORMA` (body-axis accelerations), `IWD`/`IWS` (independent IRS-only wind estimate), `DRFTA`, `PHDG`.
- **Parser status:** `parsers/ice_l.py` only reads `ATX`, `PSXC`, `RHUM`, `MRTDLL_MC`, and position — none of the above dereferenced. The campaign's other raw subdirectories (`cfdc-in`, `cvi`, `dmt-caps`, `dri-ccn`) are microphysics/aerosol-only, confirmed no turbulence content there.

### IPHEX
- **Raw format:** single combined `.iphex` file per flight (UND Citation II, Ophir instrument label), no separate nav/met sub-files — the turbulence variables are in the **same file already opened** for Tair_C/P_hPa. 1 Hz.
- **Variables found:** `TAS`/`IAS`/`MachNo_N`, `Pitot_Wing`, `POS_Roll`/`POS_Pitch`/`POS_Head`, `POSZ_Acc`, `Alpha`/`Beta` (angle of attack/sideslip), `VERT_VEL`, `Wind_Z` (vertical wind, >99% valid in most flights checked, 46-91% depending on flight in others), `Wind_M`/`Wind_D`, `TURB` (EDR).
- **Parser status:** `load_iphex_file()` reads the full ~50-column header via `pd.read_csv(..., names=columns)` (line 230) — every variable above is already in `df`. `extract_iphex_standard()` (lines 365-418) never references any of them. **This is the cheapest campaign to extend** — no new file discovery needed at all, just new dict keys.
- **Caveat:** `load_iphex()` explicitly skips any file with "Combined" in its name (line 345), unrelated to turbulence but worth knowing.

### ISDAC
- **Raw format:** two independent sources.
  - `wolde-convair/*.cdf` (NRC Convair-580, **5 Hz** — the highest native rate found in this survey) — **entirely unused**, zero references anywhere in the repo. Contains `TDREDDY` (a proprietary TAMDAR eddy/turbulence coefficient, not a standard EDR), `VWND_P` (vertical wind from a Rosemount-858-style pod probe), `EWND`/`NWND` (horizontal wind components from two independent sources), `ALPHA`/`BETA`, `PITCH`/`ROLL`/`HDG`, `PRATE`/`RRATE`/`YRATE` (angular rates), `ANORM`/`ALAT`/`ALNG`/`AVERT` (accelerations).
  - `strapp-convair_bulk/CommaDelimited/*.txt` (1 Hz, averaged from the 5 Hz source per its README) — **this is the file the parser reads**. Contains `ALPHA`, `BETA`, `PITCH`, `ROLL`, `driftA`, `HDG`, `TRK`, `MWSpd`/`MWDir`, `VWND_P` (vertical wind, present at 1 Hz here too), `BmTAS`/`BmLAS`.
- **Parser status:** `load_isdac_file()` reads every column of the bulk `.txt` generically via `pd.read_csv(..., names=columns)`, so all of the above are in the raw DataFrame — but `extract_isdac_standard()` (lines 325-362) only selects Timestamp/temperature/pressure/Si/qv/position. The 5 Hz `.cdf` source (with `TDREDDY` and higher-rate everything) is not read at all.

### MACPEX
- **Raw format:** `.ict`, MMS instrument split into `MMS-FlightPath` (position + TAS) and `MMS-Met` (P/T/theta/wind) files, separate from 6 water-vapor-only instrument files (CIMS/CLH/DLH/HWV/JLH/ULH, zero turbulence content). 1 Hz.
- **Variables found:** `TAS` (FlightPath), `U`/`V`/`W` (Met — vertical wind confirmed populated in 14/16 files checked; 2 early files have 100% fill/no valid W). **No EDR, Reynolds number, or attitude fields exist in the archived files** — the file headers document a 20 Hz product (`TURB`/`REYN`/`ROLL`/`HDG`/`PIT`/`AOA`/`YAW`) as available on request from the original source, but it is not present anywhere in this repo's raw archive.
- **Parser status:** `MMS-Met_U`/`V`/`W`/`THETA` and `MMS-FlightPath_TAS` all read generically into the merged DataFrame; `load_macpex()`/`extract_macpex_standard()` reference none of them.

### MC3E
- **Raw format:** single combined `.mc3e` file per flight (UND Citation II lineage), no sub-files — unusually, this is the one campaign where the loader itself does **not** subset columns.
- **Variables found:** `Wind_Z` (vertical wind), `Wind_M`/`Wind_D`, `TURB` (EDR), `Alpha`/`Beta`, `POS_Roll`/`POS_Pitch`/`POS_Head`/`POS_Trk`, `POSZ_Acc`, `VERT_VEL`, `TAS`/`IAS`/`MachNo_N`, `Pitot_Wing`, `POS_Spd` — 17 turbulence-relevant fields, the richest single-file set in the survey.
- **Parser status:** `load_mc3e_file()` (lines 26-71) reads **all 44 columns** and `return df`s the whole thing with no subsetting at all — every field above genuinely exists as a live column in the intermediate DataFrame that `main.py` builds from `load_mc3e()`. It is only `extract_mc3e_standard()` (lines 112-169) that discards them down to the 13-column standard schema. **Second-cheapest campaign to extend after IPHEX** — the data isn't just parsed, it's fully validated/typed already.

### MIDCIX
- **Raw format:** WB-57, only two file types present: `JW*.WB57` (water vapor, no turbulence content) and `FP/*.WB57` (MMS flight path — position + TAS only).
- **Variables found:** `TAS` only. **This is a genuine absence, not a coverage gap in the exploration** — unlike its sibling campaign CRYSTAL-FACE-NASA (same WB-57/MMS aircraft system), this archive was never supplied with the MMS meteorology (wind U/V/W) or turbulence (EDR/Reynolds) product files; no MM/MG/NM/NP/FT/PT-equivalent directory exists anywhere under `data/raw/MidCix/`.
- **Parser status:** `TAS` is read (via the shared `load_mms_file` imported from `crystal_face_nasa.py`) then discarded, same pattern as elsewhere. **The weakest campaign in this survey** — even if fully extended, MIDCIX would contribute only airspeed, nothing about wind or attitude.

### MPACE
- **Raw format:** `.mpace`, single combined file per flight (14 files), NASA Ames FFI 1001, explicit "1 Hz Data" / `DX(1)=1.0` in every header.
- **Variables found:** `TURB_n`/`TURB` (dual nose+wing EDR channels — the only campaign with two independent EDR estimates), `Wind_X_Nose`/`Wind_Y_Nose`/`Wind_Z_Nose` (full 3-axis wind vector), `Wind_M_Nose`/`Wind_D_Nose`, `Alpha`/`Beta`, `POS_Pitch`/`POS_Roll`/`POS_Head`, `POSX_Acc`/`POSY_Acc`/`POSZ_Acc` (3-axis acceleration), `VERT_VEL`, `IAS_n`/`IAS_w`/`TAS`, `Pitot_Nose`/`Pitot_Wing`.
- **Parser status:** `load_mpace_file()` reads all 49 columns via `pd.read_csv(..., names=columns)`; `extract_mpace_standard()` (lines 208-232) keeps only temperature/pressure/position (Si/qv are already NaN campaign-wide per `CLAUDE.md`, since MPACE flew no water-vapor instrument — but that limitation is independent of the wind/turbulence fields, which are fully present and unaffected by the water-vapor gap).

### OLYMPEX
- **Raw format:** `.olympex`, single combined file per flight (20 files), NASA Ames FFI 1001, "1 Hz Data."
- **Variables found:** `TURB` (wing-only EDR — one channel, unlike MPACE's nose+wing pair), `Wind_Z` (vertical wind), `Wind_M`/`Wind_D`, `Alpha`/`Beta`, `POS_Roll`/`POS_Pitch`/`POS_Head`, `POSZ_Acc`, `VERT_VEL`, `TAS`/`IAS`/`MachNo_N`.
- **Parser status:** `load_olympex_file()` reads all 53 columns; `extract_olympex_standard()` (lines 156-204) keeps only temperature/frost-point/pressure/position.

### POSIDON
- **Raw format:** `.ict`, MMS instrument file separate from water-vapor files (DLH/NOAA, no turbulence content). 1 Hz.
- **Variables found:** identical variable set to ATTREX (same PI/instrument): `TAS`, `U`/`V`/`W` (vertical wind, confirmed populated across all files checked, one partial gap), `TEDR`, `REYN`, `ROLL`/`PITCH`/`HDG`.
- **Parser status:** identical situation to ATTREX — `_parse_ict_file()` reads everything generically (prefixed `MMS-1HZ_*`), `load_posidon()`/`extract_posidon_standard()` reference none of the turbulence fields.

## Recommendations (for discussion, not yet implemented)

1. **Quick wins first (11 campaigns):** ATTREX, CRYSTAL-FACE-NASA (MM/NP
   subset), CRYSTAL-FACE-UND, ESCAPE, IPHEX, ISDAC (bulk file), MACPEX,
   MC3E, MIDCIX (TAS only), MPACE, OLYMPEX, POSIDON already parse the
   relevant columns into memory — extending each `extract_*_standard()`
   to keep a few more columns is a small, low-risk change per campaign
   with no new file-discovery logic needed. MC3E and IPHEX are the
   cheapest (single already-open file, already-parsed columns).
2. **New read paths needed (4 sources):** AIRS-II, ICE-L (add `ds["WIC"]`
   etc. to the existing xarray loaders), ISDAC's 5 Hz `wolde-convair/*.cdf`
   source, ESCAPE's `atmospheric-and-aircraft-state/*.nc` source (different
   aircraft than what's currently ingested — would need its own
   integration path, not a merge into the existing Learjet stream),
   CRYSTAL-FACE-NASA's `MG`/`FP`/`FT`/`PT` directories.
3. **Schema decision needed before any of the above:** what do the new
   standard columns get called, and how are the three unit conventions
   (log10 kW/kg `TEDR`, linear cm^(2/3)·s⁻¹ `TURB`, ARM's undocumented-scale
   `Turbulence_eps`, ISDAC's proprietary `TDREDDY`) reconciled or kept
   separate (à la the existing `Si_<instrument>` per-instrument-suffix
   pattern)?
4. **Sub-second data conflicts with the exact-second merge convention:**
   ARM (4 Hz) and ISDAC's unused wolde-convair source (5 Hz) are the two
   highest-rate sources found. Flooring to 1 Hz (like every other parser
   already does) discards most of the signal turbulence analysis would
   want; carrying native rate would mean a data structure genuinely outside
   the current L0/L1/L2 tier scheme. This should be settled before writing
   any code, not discovered mid-implementation.
5. **MACPEX and MIDCIX will remain weak even after extension** — MACPEX's
   archived files lack EDR/attitude entirely (only in an unarchived 20 Hz
   product not present here), and MIDCIX has nothing beyond airspeed. Any
   cross-campaign turbulence analysis should expect these two to be
   thin/absent regardless of parser changes.
