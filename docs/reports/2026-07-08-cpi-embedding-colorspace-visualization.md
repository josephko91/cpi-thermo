# CPI Embedding Color-Space Visualization: Si vs Tair

Renders each CPI particle image's 384-dim `cls_features` embedding as a
single color and plots it in Si-Tair thermodynamic phase space — a visual
complement to `docs/reports/2026-07-07-env-to-morphology-multivariate-analysis.md`'s
numeric env→morphology analysis. Three dimensionality-reduction methods
(PCA, UMAP, t-SNE) are each run as an independent variant reducing the
384 dims to 3, which are mapped to RGB, converted to HSV, and rendered
via 5 different colormaps applied to Hue. A second, complementary view
bins Si-Tair space into a 2D grid and colors each bin by the *mean*
embedding-color of its member images, at 3 grid resolutions.

Full CSVs: `logs/visualize_embedding_colorspace/latest/`. Figures:
`figs/visualize_embedding_colorspace/latest/`. Reproduce with
`python scripts/visualize_embedding_colorspace.py` (conda env `cpi-thermo`
— see Method for package requirements). Total runtime: **10.0 minutes**
(well under the 3-hour target; see §5).

## 1. Method

### 1.1 Data

`data/out/combined_env_data_L2.parquet` (1,828,818 rows — L2 tier, every
core variable present by construction) joined to
`data/raw/SSL-Model-v3/cpi3m_campaign_cls_head_features_compressed.parquet`'s
`cls_features` (384-dim backbone CLS-token embedding) via the same
memory-safe streamed join used by `analyze_data_tiers.py` and
`analyze_embedding_multivariate.py` (`load_l2_embeddings`). All
1,828,818 L2 rows matched an embedding (100%). Only `Campaign`,
`cpi_filename`, `Tair_C`, `Si` are loaded from L2 (not all ~40 columns),
and each embedding vector is standardized (z-scored per dimension,
float32) before any reduction.

### 1.2 Representative subsampling

A single random subsample of **50,000 rows** (seed 42) is drawn from the
full 1,828,818-row population and used to fit **all three** reduction
methods — the same 50,000 points, so PCA/UMAP/t-SNE are directly
comparable "variants" of the same reduction task rather than different
methods run on different data.

Why 50,000 is representative: a simple random sample of size *N* from a
population has a worst-case margin of error on any subgroup proportion
of ~√(0.25/N) (95% CI, conservative p=0.5 case) — at N=50,000 that's
~0.45%. This is checked empirically, not just asserted (§2, figure 01):
a two-sample KS test comparing the full population's Tair_C/Si
distributions against the subsample's gives KS statistics of 0.0042 and
0.0037 (p=0.34 and p=0.52) — indistinguishable from sampling noise.

### 1.3 Reduction methods

| Method | Fit population | Notes |
|---|---:|---|
| PCA | full 1,828,818 | linear, cheap (2.1s) even at full scale — no need to subsample the fit itself |
| UMAP | 50,000 | `n_neighbors=30, min_dist=0.1, n_components=3`; `.transform()` used separately to project 500,000 more points (not in the fit set) for the heatmap population only |
| t-SNE | 50,000 | 384-dim input first PCA-reduced to 50 dims (standard practice — high-dim distance computation is slow and noisy for the perplexity-based neighbor search); `n_components=3, perplexity=30, init="pca"` |

PCA's 3 retained components capture only **10.2%** of the 384-dim
variance (figure 02) — expected and consistent with
`docs/reports/2026-07-07-data-tier-descriptive-analysis.md`'s finding
that `cls_features`' variance is spread fairly evenly across many
components (that report's top-10 PCs captured ~27%). This is exactly why
UMAP/t-SNE are included as variants: they optimize for preserving local
neighborhood structure rather than variance, so a 3-component reduction
can be much more visually informative than PCA's 3 components even
though PCA is the "explained variance" gold standard for linear methods.

t-SNE has no out-of-sample extension (`.transform()` does not exist for
the classic algorithm), so it is scatter-only — no t-SNE-based binned
heatmap was attempted.

### 1.4 Color pipeline

For each method's 3 components: min-max normalize each component
independently over its own fit population to `[0,1]`, treat the triple
as `(R,G,B)` — a valid "true color" rendering, shown on its own (figure
04) — then convert to HSV via `matplotlib.colors.rgb_to_hsv` and re-color
by passing the Hue channel through a chosen matplotlib colormap (figures
05-07). This second step exists because raw RGB from 3 arbitrary
reduction axes is frequently low-contrast/muddy (real components rarely
span the full unit cube), while Hue is a single perceptually-meaningful
scalar a well-designed colormap can spread across the full visual range.

Five colormaps are compared side-by-side per method (figure 03 is the
shared legend): `hsv`, `twilight`, `twilight_shifted` (all three
**cyclic**, matching Hue's own 0≡1 wraparound — no visible seam),
`turbo` (a modern rainbow-family map, high local contrast but not
cyclic) and `viridis` (perceptually-uniform sequential — included
deliberately as a "wrong tool" comparison: sequential maps show a hard
seam wherever Hue wraps past 1→0, visible as an abrupt color jump in the
`viridis` panels that the cyclic maps don't have).

### 1.5 Binned / smoothed heatmap

Si-Tair space is divided into a 2D grid; each occupied bin's color is
the **mean of its member images' raw (pre-normalization) 3 components**,
then the *same* global min-max/HSV mapping from §1.4 is applied to that
mean — averaging before normalizing/HSV-converting avoids any circular-
mean artifact from averaging Hue angles directly.

**Grid resolution** (3 variants, figures 08-09): base bin counts per axis
are set via the Freedman-Diaconis rule (`h = 2·IQR/n^(1/3)`, computed
independently for Tair_C and Si over the full 1,828,818-row population,
clipped to [8, 200]) — both axes independently resolved to a 200-bin FD
suggestion. "coarse"/"medium"/"fine" are 0.25x/0.5x/1x that base
resolution (50x50 / 100x100 / 200x200 bins).

**Minimum sample count per bin** (statistically grounded, not an
arbitrary constant): `max(30, ceil(0.1 × median_nonzero_bin_count))` —
30 is the standard CLT rule-of-thumb floor for an approximately-normal
sampling distribution of a mean; the 10%-of-median term adapts the
threshold to each resolution's actual bin density (finer grids naturally
have fewer points/bin) rather than using one fixed number everywhere.
Bins below threshold are left unfilled/transparent (background shows
through) rather than drawn with a noisy few-sample average.

**Heatmap population size** differs by method, matched to what each can
scalably produce: PCA uses the **full 1,828,818-row population** (its
transform is linear and free); UMAP uses its 50,000-point fit set plus
500,000 more points projected via `.transform()` (550,000 total) — both
far larger than the 50,000-point scatter alone, giving much more robust
per-bin statistics (§2, bin retention tables) than the shared subsample
could on its own.

## 2. Results

### 2.1 Representativeness & PCA variance (figures 01-03)

- `01_subsample_representativeness_check.png`: full-population vs.
  50,000-point subsample histograms for Tair_C and Si — visually and
  statistically (KS p=0.34, p=0.52) indistinguishable.
- `02_pca_variance_explained.png`: PC1/PC2/PC3 each capture only
  3.2-3.6% of variance (10.2% combined) — `cls_features`' variance is
  spread broadly, not concentrated in a few axes.
- `03_colormap_hue_legend_strip.png`: the Hue→color mapping used by
  every colormap-comparison figure below.

### 2.2 Scatter: truecolor by method (figure 04)

Same 50,000 points, 3 panels (PCA / UMAP / t-SNE), true RGB (no
colormap). All three show the same qualitative pattern: **strong,
visible color banding along the Tair axis** (cold micro-physical regimes
cluster into similar colors — image morphology genuinely differs by
temperature) and **much weaker structure along Si** (points at a fixed
Tair span a wide range of colors regardless of Si). This matches the
directional finding in the multivariate-analysis report — of the 7 env
variables, temperature-adjacent ones dominate morphology explanatory
power, while Si's relationship is comparatively weak — now visible
directly rather than only as an R²/SHAP number.

### 2.3 Scatter: Hue→colormap comparison, 5 variants (figures 05-07)

One figure per method (PCA/UMAP/t-SNE), each with 5 colormap panels. The
three cyclic maps (`hsv`, `twilight`, `twilight_shifted`) render the same
underlying structure without a seam; `turbo` gives higher local contrast
at the cost of not being cyclic; `viridis` visibly seams wherever Hue
wraps — a concrete illustration of why colormap choice matters for
circular quantities, not just a stylistic preference.

### 2.4 Binned / smoothed heatmap (figures 08-09)

| Method | Resolution | Bins (Tair×Si) | Occupied | Retained (min n) | Median n (occupied) |
|---|---|---:|---:|---:|---:|
| PCA (n=1,828,818) | coarse | 50×50 | 843 | 649 (77.0%) | 261 |
| PCA | medium | 100×100 | 2,413 | 1,784 (73.9%) | 145 |
| PCA | fine | 200×200 | 6,262 | 4,280 (68.3%) | 78 |
| UMAP (n=550,000) | coarse | 50×50 | 846 | 567 (67.0%) | 84.5 |
| UMAP | medium | 100×100 | 2,389 | 1,421 (59.5%) | 50.0 |
| UMAP | fine | 200×200 | 6,096 | 2,961 (48.6%) | 27.0 |

Both methods' heatmaps make the same Tair-dominant / Si-weak structure
from §2.2 visually unambiguous once smoothed: a clear color gradient
sweeps across the Tair axis at every resolution, while moving vertically
(Si) within a Tair column changes color much more subtly. UMAP's
heatmap (smaller population, 550k vs PCA's full 1.83M) retains a lower
percentage of bins at "fine" resolution (48.6% vs 68.3%) — expected,
since the same 200×200 grid has ~3.3x fewer points to fill it; this is
exactly why UMAP's heatmap population was deliberately built up via
`.transform()` beyond the 50,000-point fit set (§1.5) rather than left
at 50,000, which would have retained far fewer bins still.

heatmap extra) finished in 6.2 minutes; given the ~18x remaining budget
margin against the 3-hour target, sample sizes were increased to the
50,000 / 500,000 used above for better statistical robustness, at only
~4 additional minutes of runtime.
