# L0/L1/L2 Descriptive Analysis + CPI Embedding / Environment Relationship

Descriptive statistics for every core variable at each of the three data
tiers (`data/out/combined_env_data.parquet` = L0,
`combined_env_data_L1.parquet` = L1, `combined_env_data_L2.parquet` = L2 —
see `docs/decisions/2026-07-07-exact-second-merge-rewrite.md` for the tier
definitions), plus an investigation into whether CPI particle-image
embeddings carry information about the environmental conditions each
image was captured in — run against both embeddings the SSL model
provides (`head_features`, 64-dim classification-head features, and
`cls_features`, 384-dim backbone token features) on the identical L2 cut.

Full CSVs: `logs/analyze_data_tiers/latest/`. Figures:
`figs/analyze_data_tiers/latest/`. Reproduce with
`python scripts/analyze_data_tiers.py`.

## 3. L2: CPI embedding / environment relationship

### Method

Embeddings source: `data/raw/SSL-Model-v3/cpi3m_campaign_cls_head_features_
compressed.parquet` — a self-supervised model provides two feature vectors
per CPI image: `head_features` (64-dim, classification-head output) and
`cls_features` (384-dim, backbone CLS-token output). Both are joined to
L2 on `(campaign, filename)`. All 1,828,818 L2 rows matched an embedding
for both sources (100%).

**Regression uses each embedding's full dimensionality** (all 64 dims for
head_features, all 384 for cls_features), not a small fixed number of PCA
components — an earlier version of this analysis used a fixed top-10 PCs
for both, which is 15.6% of head_features' total dims but only 2.6% of
cls_features', unfairly truncating the larger embedding far more than the
smaller one. The regression is OLS with intercept, solved via the normal
equations (a D×D solve, D≤384) rather than SVD-based `lstsq` for memory
reasons (SVD's O(n·D) working set was several GB at n≈1.8M and D=384 on
this project's 16GB machine); features are standardized first, so no
information is lost relative to a full-rank PCA rotation. PCA (top 10
components only) is still computed and reported separately, purely for
the variance-explained table and the 2D scatter plots below — it plays no
role in the regression numbers.

### Pooled result (all campaigns together)

Held-out R² (80/20 split, OLS on the **full embedding**, all dims)
predicting each core variable, head_features vs cls_features:

| Variable | head_features R² (64 dims) | cls_features R² (384 dims) |
|---|---:|---:|
| Lon | 0.626 | **0.960** |
| Lat | 0.717 | **0.959** |
| Alt_m | 0.518 | **0.790** |
| P_hPa | 0.520 | **0.777** |
| Tair_C | 0.403 | **0.689** |
| qv | 0.181 | **0.459** |
| Si | 0.091 | **0.234** |

**cls_features outperforms head_features on every single variable** —
often substantially (Tair_C 0.40 vs 0.69, qv 0.18 vs 0.46). This makes
sense once regression uses the full embedding: cls_features is a strictly
larger, less-compressed representation, so it can only carry *more* raw
visual information, not less. Lat/Lon reaching R²=0.96 for cls_features
is worth a specific caution: this is likely close to "which campaign is
this image from" being near-perfectly recoverable from the full 384-dim
embedding (each campaign flew in one general region, and campaign-specific
camera/compression/calibration artifacts could contribute to this beyond
genuine geophysical signal) — see the within-campaign check below for why
this doesn't fully explain the other variables.

`figs/analyze_data_tiers/latest/l2_embedding_pca_by_env.png` (head_features)
and `l2_embedding_cls_pca_by_env.png` (cls_features) illustrate the pattern
underlying this (using just the top-2 PCs, for visualization only): a
visually distinct tail of points is colored uniformly dark (very cold
Tair_C, very low P_hPa, very high Alt_m) — this tail is ATTREX's
stratospheric flights (up to ~17,800m, temperatures to -86°C), sitting in
a clearly separate part of embedding space from every other campaign's
mid-troposphere cirrus. `l2_embedding_pca_by_campaign.png` confirms ATTREX
(and to a lesser extent ISDAC and CRYSTAL-FACE-UND) form partially
separated clusters, while most campaigns overlap heavily in the
embedding's core.

**This raises an obvious question: is the pooled R² just "which campaign
is this image from" leaking through, or is there a real relationship?**

### Within-campaign result (isolates the cross-campaign confound)

Re-standardized and re-ran the full-dimension regression *separately
within* each of the four largest campaigns (own mean/std per campaign, so
no cross-campaign structure can leak in), head_features vs cls_features:

| Variable | ATTREX head / cls | CRYSTAL-FACE-UND head / cls | ISDAC head / cls | MC3E head / cls |
|---|---:|---:|---:|---:|
| Alt_m | 0.327 / **0.401** | 0.175 / **0.450** | 0.495 / **0.628** | 0.106 / **0.189** |
| P_hPa | 0.293 / **0.375** | 0.170 / **0.444** | 0.494 / **0.624** | 0.100 / **0.186** |
| Tair_C | 0.329 / **0.403** | 0.174 / **0.448** | 0.417 / **0.557** | 0.086 / **0.166** |
| qv | 0.103 / **0.206** | 0.157 / **0.432** | 0.317 / **0.450** | 0.081 / **0.155** |
| Lat | 0.119 / **0.206** | 0.117 / **0.351** | 0.225 / 0.301 | 0.127 / **0.322** |
| Lon | 0.048 / 0.100 | 0.104 / **0.366** | 0.186 / 0.278 | 0.076 / **0.251** |
| Si | 0.047 / **0.069** | 0.047 / **0.141** | 0.072 / 0.124 | 0.093 / **0.152** |

**The relationship is real, not just cross-campaign leakage** (confirmed
by both embeddings, at every campaign). For ISDAC, within-campaign R² for
Tair_C/Alt_m/P_hPa (0.42–0.63) is *higher* than either embedding's pooled
figure — this Arctic mixed-phase cloud campaign spans a wide
altitude/temperature range with correspondingly large real changes in
imaged particle habit and size (rimed vs. pristine, size sorting with
height). ATTREX also retains a substantial within-campaign relationship
even after removing the cross-regime separation from other campaigns —
consistent with real habit changes across its own altitude range as the
aircraft profiles through the tropopause region. **cls_features wins
within every campaign too, often by a wide margin** (e.g.
CRYSTAL-FACE-UND qv: 0.157 vs 0.432) — the larger representation's
advantage isn't just a pooled/cross-campaign artifact.

**Si is the weakest relationship in every single split, for both
embeddings — but it is not zero.** With the full 384-dim cls_features,
Si reaches R²=0.234 pooled and 0.07–0.15 within campaign — a real,
detectable signal, just consistently and substantially weaker than every
other variable (roughly a third to a half of qv's R², which is itself the
second-weakest). This is more nuanced than "no relationship": ice
supersaturation is an instantaneous gas-phase property, so it's
physically sensible that it leaves a much fainter imprint on particle
imagery than temperature-driven habit growth does, but the fainter signal
is still there once enough embedding dimensions are used to find it.

### head_features vs cls_features: which encodes more environmental signal?

**cls_features wins, consistently and by a substantial margin, on every
variable in both the pooled and within-campaign checks.** This reverses
what an earlier, methodologically flawed version of this analysis found
(truncating both embeddings to the same top-10 PCs made head_features
look better, because that budget is a much larger *fraction* of
head_features' 64 dims than of cls_features' 384). Once each embedding's
full information is used, the larger, less-compressed cls_features
representation is unambiguously more predictive of the environment,
across temperature, pressure, altitude, water vapor, position, and even
the weak Si relationship. This is the expected, unsurprising result for
comparing a 384-dim representation against a 64-dim one derived from it —
the interesting finding in this analysis is less "which embedding wins"
and more the variable-level pattern (temperature/altitude/pressure
strongly encoded, supersaturation weakly but genuinely encoded) that
holds under *either* embedding.

### Interpretation

CPI particle-image embeddings meaningfully encode **temperature,
pressure, altitude, and position** — consistent with classical ice-crystal
habit diagrams (crystal shape is a well-documented function of formation
temperature) — and this holds using *either* embedding source, and is
confirmed to hold *within* single, more heterogeneous campaigns (ISDAC,
ATTREX, CRYSTAL-FACE-UND), not just as an artifact of pooling visually
distinct campaigns together. **Ice supersaturation (Si) is consistently
the weakest relationship** — real but markedly fainter than every other
variable, in every campaign, using either embedding. Si has 100% valid
coverage in L2 by construction, so this is a genuine physical/visual-encoding
finding, not a data-quality artifact.

## 4. Caveats

- Regression R² uses OLS (linear) on the standardized embedding; a
  nonlinear model could recover more of the relationship, particularly
  for the weaker ones (qv, Si). The numbers here are a linear lower bound
  on predictability, not an upper bound.
- A tiny ridge term (1e-6 on the normal-equations diagonal) guards against
  collinearity among embedding dimensions; at D≤384 vs n≈1.8M rows this
  has negligible effect on the reported R² but means the fit isn't exact
  OLS in the degenerate-collinearity case.
- Within-campaign checks used only the 4 largest campaigns (>100k L2 rows
  each); smaller campaigns weren't checked individually and could behave
  differently.
- The embeddings-loading step streams the ~4.9GB archive in batches
  (`scripts/analyze_data_tiers.py::load_l2_embeddings`) and the regression
  is solved via the normal equations rather than SVD-based `lstsq`
  (`ols_r2`), both because this project's 16GB development machine can't
  hold the full embedding archive or an SVD-sized working set for n≈1.8M,
  D=384 at once. Neither should change the numbers versus an unconstrained
  machine, only what's feasible to run here.
- The very high pooled Lat/Lon R² for cls_features (0.96) likely reflects
  substantial "which campaign/platform is this" leakage (camera,
  compression, or calibration artifacts specific to each campaign's CPI
  unit) on top of any genuine geophysical signal — not disentangled
  further here.
